# Работа в монорепозитории

- Зависимости, приложения, миграции, линтеры и тесты запускаются **только в Docker**.
  Не устанавливать Python/npm-пакеты на хосте, не создавать на хосте `.venv`,
  `__pycache__`, кэши тестов и сборочные артефакты.
- Разработка: `compose.dev.yaml`, команды в `Makefile`. Production-сборки:
  `compose.prod.yaml`. Автотесты используют отдельный временный стенд
  `compose.test.yaml`; не направлять их в dev/prod БД.
- Python-зависимости фиксируются в `uv.lock` командой `make lock` внутри контейнера.
  Окружение находится в `/opt/venv` образа. JS-зависимости — в образе frontend.
- Бизнес-решения: `docs/decisions.md`; исходное задание: `docs/source/assignment.md`.
  Актуальные ТЗ по пяти компонентам — `docs/spec/`; при расхождении сверять
  последнее принятое решение. `docs/implementation/` описывает фактическую
  реализацию и не меняет требования само по себе.
- Приложения находятся в `apps/frontend`, `apps/gateway`, `apps/users`,
  `apps/booking`, `apps/assistant`; общий Python-код — в `packages/platform`.
  Сохранять чужие правки и пользовательские данные; при изменении контрактов
  обновлять типизированный клиент и соответствующую документацию.
- Не удалять Docker volumes с пользовательскими данными. Тестовый стенд и его
  временные данные удаляет собственный `scripts/test.sh`.
