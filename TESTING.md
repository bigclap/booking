# Проверки и результаты

Воспроизводимые команды и историческая сводка по
[исходному заданию](docs/source/assignment.md). Историческая таблица относится
к **12.11.2026**, до переноса приложений в единую структуру `apps/`;
проверки после очистки записаны отдельно. Целевые наборы пересекаются
с полным, поэтому количества не суммируются. Живой вызов LLM отделён
от тестовых моделей; операторские отчёты конкретных размещений сюда не входят.

## Команды

Из корня проекта, только в Docker. Серверные тесты используют отдельный
[compose.test.yaml](compose.test.yaml) с временными PostgreSQL/NATS, без dev/prod БД.

```bash
docker compose -f compose.test.yaml build tests
make test
make lint
sh scripts/prove-booking-guard.sh
```

`make test` вызывает [scripts/test.sh](scripts/test.sh): поднимает временные
PostgreSQL и NATS, запускает pytest, удаляет только этот тестовый стенд.
Эксперимент защиты использует свой временный Compose project и очищает его.
Обычные dev/prod volumes эти процедуры не используют.

Целевой набор Booking с тем же изолированным lifecycle:

```bash
sh scripts/test.sh pytest -q apps/booking/tests
```

При уже собранном dev-стенде:

```bash
docker compose -f compose.dev.yaml run --rm --no-deps frontend npm test
docker compose -f compose.dev.yaml exec -T frontend npm run build
make smoke
make prod-smoke
```

`make smoke` проверяет работающий dev. `make prod-smoke` собирает отдельный
временный локальный production-стенд и удаляет его после проверки;
не является проверкой публичного домена/TLS.

## Конкурентность с настоящим сервером и хранилищем

[Интеграционный тест](apps/booking/tests/test_bookings_http_integration.py)
запускает Uvicorn, посылает **100 одновременных TCP HTTP-запросов**
и проверяет результат в PostgreSQL:

- один ресурс: один успех, остальные — конфликт;
- комната и её место: одновременно не сохраняются несовместимые брони;
- в БД одна бронь, одна запись подтверждения и одно логическое событие.

Дополнительно проверяются соседние интервалы, разные места, повтор ключа,
изменённые параметры под прежним ключом, перенос/продление, текущая бронь,
пометки, снимки удалённых ресурсов, вместимость и повторная доставка событий.
Это проверка внутреннего реального HTTP-сервера Booking с БД; внешний
публичный стенд и нагрузочный SLA ею не подтверждаются.

## Эксперимент с отключённой защитой

```bash
sh scripts/prove-booking-guard.sh
```

[Скрипт](scripts/prove-booking-guard.sh) выполняет три шага:

1. Исходный конкурентный тест с работающей защитой проходит.
2. В отдельном одноразовом Python-процессе `check_conflicts` временно
   заменяется на no-op. Тот же тест ожидаемо падает: **`assert 100 == 1`**,
   ошибочно сохранились все сто запросов.
3. В свежем процессе исходная защита снова проходит тот же тест.

Исходники не переписываются, постоянного выключателя защиты нет.
Скрипт требует именно ожидаемого падения, а не любой ошибки запуска.
Записанный результат: [Booking](docs/implementation/booking-service.md#проверки).

## UI и отказы AI

На историческом dev-этапе 12.11.2026 вручную проверены серверный вход, импорт офисов, создание,
перенос, редактирование, отмена, отказ устаревшей версии с `409`,
сохранение плана/настроек, возврат к форме после входа, пустая прошедшая дата,
отказ скрытого офиса и просмотр архива. Проверочные брони отменены,
исходный браузерный архив сохранён:
[отчёт UI](docs/implementation/frontend-integration.md#проверки).

Живой LLM-прогон сначала получил неверные аргументы рабочего места:
сервер отказал и не создал бронь. После исправления обработки tool errors
успешный прогон показал форму и создал ровно одну бронь только по подтверждению.
Контрольная бронь отменена, история сохранена. Детерминированные тесты отдельно
проверяют исправление аргументов, исчерпание конечного retry-бюджета и отказ
невалидному предложению. Реальный провайдер этими автотестами не вызывается.

## Дополнительные сквозные проверки

Следующие проверки не описаны как завершённые в перечисленных отчётах:

| Проверка                                          | Требуемое доказательство                                                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Сохранность после перезапуска                     | Создать бронь, перезапустить сервис/БД с постоянным volume, прочитать ту же запись                                |
| Ручная форма при выключенном AI                   | В изолированном стенде отключить Assistant/генерацию, открыть план и успешно создать/отменить бронь вручную       |
| Полная мобильная приёмка интегрированного клиента | Проверить касания ресурсов, карту, шкалу, формы и размеры touch targets на портретном телефоне                    |
| Сторонний интерфейс MCP                           | Официальный SDK и собственный HTTP-клиент не подменяют подключение именно ChatGPT или другого готового приложения |
| Занятые демонстрационные интервалы                | На выбранном экземпляре создать офис и контрольные интервалы через админку/форму, не заполняя чужие БД            |

Архитектурная независимость, постоянный PostgreSQL и unit-тесты не подменяют
запись этих сквозных проверок. Актуальные реализации и ограничения —
[services-status](docs/implementation/services-status.md),
[frontend-integration](docs/implementation/frontend-integration.md).
