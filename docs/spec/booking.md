# ТЗ: Booking — пространство и бронирование

**Актуализировано: 12.11.2026.** Документ задаёт требуемое поведение сервиса,
а не подтверждает готовность реализации. Основания: [исходное задание](../source/assignment.md),
[журнал решений](../decisions.md) до D-124, [архитектура](../architecture.md)
и [предметная модель](../domain-model.md). Последующее решение заменяет
противоречащую ему раннюю формулировку. Отложенное перечислено в разделе 11.

## 1. Назначение и владение

Booking — независимо развёртываемый Python/FastAPI-сервис, владелец двух
предметных областей: офисного пространства и бронирования. Он хранит здания,
этажи, планы, ресурсы, характеристики пространства, недельное расписание
зданий, брони и результаты их изменений.

Постоянное хранилище — собственная БД PostgreSQL со своими доступом
и миграциями в общем экземпляре PostgreSQL, D-113. Прямого доступа к таблицам
Users и Assistant нет. Приложения, миграции и проверки запускаются в Docker
по [правилам репозитория](../../AGENTS.md).

[Gateway](gateway.md) предоставляет публичные HTTP, MCP и SSE, проверяет
личность, роль, доступ к зданию и право изменить конкретную бронь. Booking
получает разрешённые команды и проверяет предметные условия. В Booking
не хранятся копии учётных записей, ролей, списков доступа к зданиям,
блокировок или отозванных JWT — D-117. ID владельца в бронях является
предметной связью, а не пользовательской базой.

Обычные вызовы Gateway → Booking идут через **Core NATS request/reply**,
надёжные фоновые команды и события — через **JetStream с transactional outbox**,
D-111, D-112, D-124. HTTP API и MCP сотрудника используют один прикладной слой
Booking через Gateway. Отдельной копии правил или MCP-хранилища нет.
Assistant использует общий HTTP MCP-вход Gateway.

## 2. Здания, планы и ресурсы

В интерфейсе «офис» соответствует зданию. Поддерживаются несколько зданий,
добавление и изменение через админку. Этаж принадлежит одному зданию,
ресурс — одному этажу. У здания собственное недельное расписание.
Внутри доступного пользователю здания доступны все этажи и ресурсы;
фильтрацию зданий выполняет Gateway, D-075, D-076, D-085.

| Данные      | Назначение                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------- |
| Здание      | Устойчивый ID, название, необязательный адрес, этажи и недельные рабочие часы                     |
| Этаж и план | Устойчивый ID, название, подложка, геометрия помещений, проходов, объектов и связей               |
| Ресурс      | Устойчивый ID, тип, название, этаж, бронируемость и при необходимости родительская переговорная   |
| Оснащение   | Виды, разновидности и количества предметов, характеристики рабочего места и вместимость помещения |
| Окружение   | Семантические типы и положение небронируемых объектов для отображения и подбора                   |

Поддерживаются рабочие места и переговорные. Каждое рабочее место — конкретный
ресурс на плане, включая отдельное место за общим столом, D-034, D-077.
Количество стульев или мест дивана само по себе не создаёт неразмеченные
бронируемые ресурсы. Помещение, его геометрия и возможность бронирования
являются разными свойствами.

Для рабочего места значимы стол, стул, монитор, клавиатура, мышь и другое
заданное оснащение; для переговорной — сидячая вместимость, стол, доска,
проектор и другое оснащение, D-035, D-074. Вместимость вычисляется по
признаку «сиденье», количеству и числу посадочных мест вида. Видами сидений
могут быть стул, кресло, мешок, фитбол, диван. Название элемента — «доска».

Конструктор допускает размещённые предметы и пространственное окружение:
окно, кофемашину, холодильник, кулер, туалет, D-045, D-087. Окружение
не является бронируемым ресурсом. Геометрическая близость в единицах плана
не выдаётся за метры или расстояние пешком через проходы. Итоговые связи
оснащения с ресурсами сверяются с [конструктором](../implementation/office-builder.md);
вывод по ближайшему предмету из локального прототипа не закрепляется
как серверный источник истины.

Интеграционная основа — [контракт Gateway](../implementation/gateway-contract.md):
строковые ID конструктора сохраняются, не заменяются требованием UUID;
настройки здания и план сохраняются отдельными командами. Сохранение плана
и обновление его ресурсной проекции выполняются одной транзакцией.
Изменение настроек не перезаписывает план, изменение плана — настройки.
Неверная геометрия, повторяющиеся ID и циклические связи отклоняются до записи.
Расширенные поля документа плана не теряются при чтении и сохранении.

Перемещение объекта или замена подложки не меняют его идентичность.
Удаление ресурса с плана сохраняет историческую ссылку и сведения для
отображения прежней брони; каскадное удаление броней не допускается.
Удалённый ресурс недоступен для новых броней, существующие затронутые
брони обрабатываются по разделу 7.

## 3. Бронь и время

Бронь содержит устойчивые ID брони, ресурса и владельца, дату и интервал,
число участников для переговорной, сведения о создании и изменении,
состояние отмены/досрочного завершения и при необходимости пометку пересмотра.
История позволяет отличить исходно согласованный интервал от досрочного
окончания и установить причину отмены. Имена полей и enum фиксируются
в схеме хранения и контракте, сохраняя эти различия.

Владелец определяется удостоверенным контекстом Gateway. Произвольный
`user_id` из формы, URL или аргументов модели не назначает владельца.
Административное изменение не подменяет владельца администратором.
Имя и фамилию для представления владельца собирает Gateway; имя не заменяет ID.

В пользовательских сценариях и правилах календаря используется
**Europe/Moscow**. Публичная форма `ClientBooking` использует дату и
`start/end` в минутах суток; адаптация внутренних представлений не меняет
московскую дату и границы интервала. Источник текущего времени — сервер.

Обязательные правила создания и изменения пользовательского интервала:

- Начало строго раньше окончания; интервал целиком находится в одной
  московской календарной дате и в рабочих часах здания этой даты, D-052.
- На каждый день недели задаётся выходной или один непрерывный рабочий
  диапазон. Перерывы и исключения для отдельных дат отложены, D-091, D-094.
- Начало и окончание кратны единому шагу. По умолчанию — пять минут,
  одинаково для формы, Ганта, HTTP и MCP, D-093.
- Шаг и горизонт задаются переменными окружения. По умолчанию горизонт —
  семь календарных дат: сегодня и ещё шесть дней по Москве, включая все
  рабочие часы последней даты, D-095.
- Новая бронь не начинается в прошлом. Ближайшее начало — ещё не прошедшая
  граница шага: при 10:02 и шаге пять минут это 10:05, D-096.
- Ввод вне сетки или правил отклоняется, без незаметного округления,
  подстановки другого ресурса или переноса времени.

Booking предоставляет действующую политику времени: часовой пояс, шаг,
горизонт, серверное время, допустимые даты и ближайшее начало. Frontend
и Assistant используют эти значения, сервер повторно проверяет их при записи.
Дополнительных ограничений длительности, не следующих из этих правил,
не вводится.

Интервалы полуоткрытые: **`[start, end)`**. 10:00–11:00 и 11:00–12:00
совместимы. Досрочное окончание «сейчас» не округляется до следующего шага
и немедленно освобождает остаток интервала, D-073, D-089.

## 4. Конфликты и доступность

Один ресурс не имеет пересекающихся действующих броней независимо
от владельца. Одновременные брони разных независимых ресурсов одним
пользователем разрешены, D-002. Цель использования не ограничена типом:
переговорную можно занять целиком одному для работы или созвона, D-036.

| Сохранённая бронь                | Несовместимое пересекающееся бронирование             |
| -------------------------------- | ----------------------------------------------------- |
| Переговорная целиком             | Та же переговорная и любое отдельное место внутри неё |
| Место в переговорной             | То же место и переговорная целиком                    |
| Другое место той же переговорной | Не конфликтует при разрешённом бронировании по местам |

Переговорная по умолчанию бронируется целиком. Администратор явно включает
для неё «Можно бронировать по местам», D-038. Требование уединения не
превращает бронь одного места в неявную блокировку остальных: пользователь
подтверждает фактический ресурс — переговорную целиком.

Проверка и запись атомарны для всего набора физически конфликтующих ресурсов,
включая конкурентную бронь комнаты и места, создание, перенос, изменение
длительности и административные операции. Решение работает при нескольких
процессах сервиса; предварительной проверки или блокировки в памяти
недостаточно. Разные свободные места не становятся взаимоисключающими
ресурсами из-за неверной модели конфликтов.

Нужны два различимых представления доступности:

1. Занятость в момент курсора для карты и сводных строк: свободно,
   частично занято, полностью занято. Частичная занятость — занята часть
   отдельных мест, часть свободна. Счётчик относится к бронируемым местам,
   не к рассчитанной по мебели вместимости, D-062, D-086.
2. Доступность ресурса **на всём выбранном интервале** для формы и подбора,
   с учётом всех связанных конфликтов, D-065. Частично занятое помещение
   нельзя занять целиком на пересекающееся время.

Для переговорной при создании обязательно число участников. Оно не равно
автоматически вместимости. Если участников больше сидячих мест, возвращается
предупреждение, подтверждение разрешено, D-041, D-069. Число участников
не освобождает места внутри уже забронированной целиком комнаты.

## 5. Создание и повтор подтверждения

Просмотр, предложение помощника, выбор ресурса и заполнение формы не
удерживают ресурс. Создание выполняется после подтверждения пользователем
ресурса, даты и времени в нашей форме; для переговорной подтверждается
число участников. Текст модели и инструмент подготовки предложения не
создают бронь, D-031, D-043, D-049, D-054.

Параметры предзаполнения передаются в URL без таймера и отдельной записи
предложения в БД, D-118. Ссылка пригодна для закладки, но не является
полномочием или ключом операции. Если её дата прошла, Frontend оставляет
дату пустой и сохраняет остальные параметры, D-119. После входа текущий
пользователь подтверждает конечные параметры; Gateway проверяет права,
Booking — актуальные условия. Автоматическая отправка результата
во внешний чат не требуется, D-121.

Клиент создаёт **Idempotency-Key** для одной отправки подтверждения и
использует тот же ключ при её повторах. Booking сохраняет ключ с бронью
в той же транзакции. Ключ относится к удостоверенному владельцу операции;
повтор возвращает ту же бронь, включая потерянный ответ или конкурентные
повторы, без повторного события создания. Изменённые параметры под тем же
ключом различимо отклоняются; новая осознанная отправка получает новый ключ.
Ключ сохраняется вместе с историей созданной брони и не становится TTL
предложения. Повтор не восстанавливает впоследствии отменённую бронь, D-120.

При конфликте или ошибке запись не создаётся, клиент получает различимую
причину и сведения о занятом интервале для формы. Успех возвращается после
фиксации данных. Ресурс и время автоматически не заменяются.

## 6. Изменение, отмена и история

Сотрудник изменяет только свою бронь; Gateway проверяет владение. До начала
доступны перенос и изменение интервала через форму и Гант. Перенос между
переговорной и отдельным местом разрешён, D-083: место рассчитано на одного,
при переносе на него число участников комнаты убирается; при переносе
места в помещение исходное число участников — один, далее доступна форма.

После начала собственной брони сотрудник изменяет только окончание;
начало и ресурс фиксированы, D-097. Сохранение исходного начала при таком
изменении не является созданием в прошлом. Новое окончание и оставшаяся
занятость проверяются по действующим правилам. Для освобождения прямо сейчас
используется досрочное завершение, D-073.

Изменение атомарно, прежняя версия исключается из проверки собственного
конфликта. При отказе прежняя бронь остаётся целой. Жест редактирования
сохраняется после завершения, без отдельного подтверждения; создание
по-прежнему выполняется через форму.

| Случай                            | Результат и занятость                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------ |
| Действующая будущая/текущая бронь | Сохранённый интервал блокирует ресурс и связанные ресурсы                            |
| Естественное окончание            | Прошедшая запись остаётся в истории; отдельная задача смены состояния не обязательна |
| Отмена будущей брони              | Запись сохраняется как отменённая, занятость освобождается                           |
| Отмена текущей брони              | Окончание обрезается по текущему времени, прошедшая часть сохраняется                |
| Требует пересмотра                | Отдельная пометка причины, не отмена и не освобождение интервала                     |

Повторная отмена не удаляет историю и не создаёт новое завершение.
Серии повторяющихся броней отложены; каждую бронь создают отдельно, D-081.

В общих просмотрах доступны интервал, имя и фамилия владельца, число
участников переговорной, D-040, D-067. Это не даёт права менять чужую бронь.
После отзыва здания Gateway скрывает его данные, включая собственные
исторические брони сотрудника; администратору история остаётся доступна,
D-100.

## 7. Административные изменения и пересмотр

Администратор управляет зданиями, расписанием, планами, ресурсами и любыми
бронями через админку, включая чужие, D-042. Административные права снимают
ограничение по владельцу, но не проверки корректности и физических конфликтов.
Общий сотруднический Гант разрешает редактирование только своих броней.
Административные инструменты в MCP сотрудника не добавляются, D-103.

Изменение часов, удаление/изменение доступности ресурса или отключение
бронирования по местам **не обрезает и не отменяет существующие затронутые
брони**: они сохраняются как есть с видимой пометкой «требует пересмотра»,
D-078, пересматривающее ранние D-060 и D-068. Новые брони следуют новым
правилам. Помеченный интервал продолжает участвовать в конфликтах, D-080.
Для пометки сохраняется объяснимая причина; ознакомление не снимает её.
Исправление сохраняется после проверки актуальных условий, D-098.

Обновление правил и определение затронутых броней согласуются с конкурентной
записью: после вступления изменения в силу новая бронь не проходит по старым
условиям. Исторические сведения позволяют показать проблему даже после
удаления ресурса с плана. Автоматическое сравнение броней с изменившимся
оснащением отложено без реализации, D-102. Внешние оповещения — дальнейшее
развитие; видимая пометка нужна в текущем интерфейсе.

**Исключение — потеря доступа пользователем**, D-089:

- при отключении/удалении сотрудника отменяются все его будущие брони,
  текущие прекращаются немедленно, прошедшая история сохраняется;
- при отзыве здания применяется тот же эффект только в этом здании,
  другие здания не затрагиваются;
- это операция над бронями по разрешённой команде Users/Gateway,
  а не локальная проекция учётной записи или прав в Booking.

Отзыв и запись задачи выполняются в Users атомарно через outbox. Booking
обрабатывает долговечную команду JetStream, фиксирует отмену/завершение
и результат, затем подтверждает доставку. Повтор безопасен, исходный момент
и область отзыва не меняются при повторной доставке. При недоступности
Booking задача сохраняется, администратор видит промежуточное состояние,
D-111. Немедленное завершение при исправной системе не означает
распределённую транзакцию во время сбоя.

Принимается компромисс короткого веб-JWT, D-116/D-117: Booking не добавляет
реестр отозванных пользователей для закрытия остаточного окна авторизации.
Ускоренный отзыв в Gateway/Redis не является обязательной частью сервиса.

## 8. Прикладные операции и события

Внутренний контракт предоставляет следующие группы операций; публичные
маршруты и преобразование моделей принадлежат Gateway:

- чтение/создание здания, чтение и сохранение настроек и планов;
- получение фактов о здании, ресурсе и владельце брони для проверки прав
  Gateway, без принятия решений о пользовательских правах в Booking;
- политика времени, каталог характеристик, занятость момента и доступность
  интервала, список и подробности броней;
- создание одной подтверждённой брони, изменение и отмена существующей;
- обработка надёжной команды отмены при утрате доступа и получение результата;
- публикация подтверждённых изменений пространства, правил и броней.

Core RPC и reply subjects отделяются от сохраняемых потоков JetStream.
Ошибки и тайм-ауты не подменяются успешным пустым ответом. Повтор после
тайм-аута создания сохраняет ключ идемпотентности: отсутствие ответа
не доказывает отсутствие сохранённой брони.

Изменение данных и outbox-событие записываются одной локальной транзакцией.
Publisher публикует в JetStream и помечает отправку после pub-ack; повтор
использует тот же event ID, D-112. Потребители идемпотентны и подтверждают
обработку после commit. Сбой между commit и публикацией не теряет действие.

Событие создания позволяет Assistant архивировать активный чат владельца
после **любой** его новой брони, включая ручную, D-082. Повтор доставки не
считается новой бронью. Изменение, отказ и повтор подтверждения существующей
брони не создают новое событие создания.

События занятости позволяют Gateway определить затронутые здание, этаж,
ресурс, родительскую комнату и связанные места, интервал и актуальную версию
изменения. События наружу отправляются после commit. Корреляция `request_id`
попытки и `trace_id` сохраняется через RPC и outbox; эти ID отличаются
от ключа идемпотентности, D-120.

Gateway доставляет обновления через авторизованный SSE, без long polling,
D-048. При исправной связи изменение становится видно другим пользователям
за пару секунд; условия измерения фиксируются в проверке. После разрыва
загружается актуальный снимок, replay всех событий не требуется, D-110.
Переход от снимка к потоку не теряет изменения; повторы и запоздалые
события не откатывают состояние.

## 9. Ошибки и изоляция отказов

Различимы ошибки полей/времени, неизвестного или удалённого ресурса,
неразрешённого способа использования комнаты, конфликта интервала,
несовместимого повтора ключа и недоступности хранилища/сервиса.
Предупреждение о числе сидячих мест не является блокирующей ошибкой.
Отказ по пользовательским правам формирует Gateway. Публичная ошибка
следует [BFF-контракту](../implementation/gateway-contract.md), не раскрывает
внутренние исключения, скрытые здания или секреты.

Неуспешная операция не оставляет частичную запись, не теряет прежнюю бронь
при переносе и не публикует незафиксированный успех. После рестарта сохраняются
планы, брони, история, ключи успешных подтверждений и неотправленный outbox.
Просмотр и ручная форма не зависят от Assistant/OpenRouter; ошибки AI
не создают бронь обходным путём.

## 10. Приёмка и обязательные проверки

Автотесты правил обязательны. Конкурентные сценарии выполняются
одновременными запросами к настоящему серверу с реальным PostgreSQL,
не только локальными функциями или заглушками. Проверки — в отдельном
временном Docker-стенде, без использования dev/prod-данных.

| Проверка                                       | Ожидаемый результат                                                                                  |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Один ресурс, соседние/пересекающиеся интервалы | Соседние разрешены; пересекающийся интервал отклонён без записи                                      |
| Разные независимые ресурсы одного владельца    | Совпадающие интервалы разрешены                                                                      |
| Конкурентное создание одного ресурса           | Успех у одного запроса, в БД одна совместимая бронь                                                  |
| Конкурентные комната и её место                | Две несовместимые брони не сохраняются; соседние интервалы разрешены                                 |
| Разные места при включённом режиме             | Совместимые параллельные брони разрешены                                                             |
| Двойное подтверждение и потерянный ответ       | Одна бронь, тот же ID при повторе, одно логическое событие создания                                  |
| Изменённые параметры с тем же ключом           | Различимая ошибка, исходная бронь сохранена                                                          |
| Конфликтный перенос или продление              | Исходная бронь не изменена; ошибка содержит данные для формы                                         |
| Время                                          | Проверены МСК, сетка, серверное «сейчас», границы дня/часов и сегодня плюс N−1 дат                   |
| Начавшаяся бронь сотрудника                    | Начало/ресурс фиксированы; окончание меняется с проверками; досрочное завершение освобождает сразу   |
| Число участников                               | Обязательно для комнаты; превышение вместимости предупреждает и допускает подтверждение              |
| Изменение часов/режима/удаление ресурса        | Затронутая бронь сохранена с пометкой и конфликтует; новая следует новым правилам                    |
| Исправление пометки                            | Ознакомления недостаточно; пометка снимается после допустимого исправления                           |
| Отзыв сотрудника/здания                        | Будущие отменены, текущие завершены, история сохранена; другое здание не затронуто                   |
| Booking недоступен при отзыве                  | Задача не потеряна, после восстановления выполнена; повтор безопасен                                 |
| Commit и outbox                                | Сбой до отправки не теряет событие; сбой после pub-ack не создаёт повторного эффекта                 |
| Рестарт и обновление плана                     | Данные и ID сохранены; настройки и план не откатывают друг друга, история не отвязана                |
| SSE и несколько клиентов                       | План и Гант обновлены, связанные ресурсы учтены; после обрыва актуальный снимок, без отката повтором |
| HTTP/MCP и права                               | Общие правила Booking; Gateway одинаково ограничивает здания/владельца, админка не обходит конфликты |
| Отказ LLM/Assistant                            | Форма и просмотр работают, ошибочной брони нет                                                       |

По исходному заданию для одного защитного теста **временно отключается
соответствующая защита**: тест обнаруживает ошибку. Затем защита
восстанавливается, итоговая исправная версия проходит проверку.
Команды и оба результата фиксируются в материалах сдачи. Конкурентный тест
нельзя заменять последовательными запросами. UI и сбои AI допускается
проверять вручную с воспроизводимым сценарием или автотестами.

Демонстрационные данные включают планы с зонами и проходами, рабочие места,
переговорные и брони для свободных, занятых и частично занятых вариантов.
Загрузка данных, миграции, команды проверок и ограничения описываются
в README. Браузерные данные автоматически не импортируются и не перезаписываются.

## 11. Отложенное и техническая конкретизация

Эти пункты не отменяют принятых правил и не требуют повторного продуктового
выбора без новой развилки:

- Согласовать формат/версии плана и справочника с параллельным конструктором;
  проверить явные связи мест и оснащения, Q-05/Q-11/Q-17.
- При реализации выбрать SQL-ограничения и блокировки для связанных конфликтов,
  индексы, миграции, точные поля истории и пометки; подтвердить их гонками.
- Зафиксировать версии NATS DTO, subjects, queue groups, тайм-ауты,
  схему outbox, retry и диагностику необрабатываемых сообщений совместно
  с Gateway/Users/Assistant; готовая Python-обвязка ещё не выбрана.
- Завершить контракт согласованного snapshot → SSE и проверить задержку
  в развёрнутом окружении; сервер и домен выбираются позже.
- Не включать сейчас календарные исключения, повторяющиеся серии,
  внешние оповещения и автоматический пересмотр по оснащению.
