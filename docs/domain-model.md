# Предметная модель

Рабочий словарь проекта. Поля и сущности ниже — проектируемая модель,
а не утверждённая схема БД или API. Границы компонентов описаны
в [архитектуре](architecture.md), причины выбора — в [журнале](decisions.md).
Неопределённости ведутся в [очереди вопросов](questions.md).

## Пользователи и доступ

| Термин                   | Смысл                                                                                                                                                                |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Пользователь / `User`    | Устойчивая идентичность человека, имя и фамилия; владелец его операций                                                                                               |
| Учётные данные           | Логин и проверочные данные пароля; хеш вместо хранения самого пароля                                                                                                 |
| Сессия входа / `Session` | Веб-вход сохраняется до явного выхода или отзыва, без автоматического выхода по сроку — D-123; короткий JWT обновляется в фоне, авторизация MCP описывается отдельно |
| Роль                     | Назначенный пользователю набор полномочий; сотрудник и администратор                                                                                                 |
| Доступ к зданию          | Администратор назначает пользователю список зданий; внутри доступны все этажи и ресурсы, остальные здания скрыты — D-085                                             |

Данные пользователя, учётные данные и сессии принадлежат Users — D-109.
Имя и фамилия задаются при создании учётной записи и показываются
как имя владельца брони. Устойчивый идентификатор не заменяется именем.
Сотрудник может сам изменить свой пароль; забытый пароль сбрасывает
администратор через админку.
Смена и сброс пароля завершают все сессии этого пользователя, включая
текущий веб-вход и MCP-клиенты; требуется повторный вход — D-092.
Реализация отзыва для короткого веб-JWT ещё согласуется с D-116;
допущенная задержка при отключении аккаунта относится к вебу и не задаёт
сроки отзыва MCP автоматически.
Механизм проверки сессий рассматривается в Q-14, управление доступом — в Q-10.
Все проверки авторизации и прав выполняет Gateway — D-117. Booking
получает разрешённые команды и проверяет предметные правила бронирования.
Идентификатор владельца остаётся в бронях как предметная связь;
состояние пользователя, роли и права в Booking не копируются.
Админка является интерфейсом управления, а не отдельным предметным доменом.
Администратор через админку управляет в том числе чужими бронями:
может изменять и отменять их. На общей шкале сохраняется редактирование
только своих броней. Административные права не отключают проверки
корректности данных и связанных конфликтов ресурсов.
При удалении сотрудника его будущие брони отменяются, текущие прекращаются
сразу и освобождают оставшееся время, прошедшая история сохраняется — D-089.
Доступ к зданиям разграничивается для пользователей — D-085; права
проверяются в Gateway одинаково для HTTP и MCP — D-117. Прежнее правило
«всем доступны все ресурсы» пересмотрено. Администратор отмечает доступные
здания у пользователя; внутри них доступны все этажи и ресурсы, остальные
здания скрыты. Начальные права при создании пользователя ещё уточняются.
MCP повторяет операции и права бэка клиентского интерфейса сотрудника;
операции административного интерфейса в него не добавляются — D-103.
При отзыве доступа к зданию будущие брони пользователя в нём отменяются,
текущие прекращаются сразу, прошедшая история сохраняется — D-089.
Брони в других зданиях не меняются.
Сохранение истории не даёт исключения из прав доступа: после отзыва
доступа к зданию пользователь не видит в том числе свои исторические брони
в нём — D-100. При полном отключении учётной записи доступ к сервису
прекращается целиком. Администратор сохраняет доступ к истории.

## Пространство

| Сущность       | Проектируемое содержание                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `Building`     | Здание офиса; несколько зданий и добавление через админку приняты в D-075, атрибуты уточняются               |
| `Floor`        | Идентификатор и название этажа, принадлежность зданию; порядок отображения ещё уточняется                    |
| `FloorPlan`    | Загруженное изображение этажа как подложка; формат файла ещё выбирается                                      |
| `Resource`     | Идентификатор, тип, название и этаж бронируемого объекта                                                     |
| `ResourceArea` | Размеченная область ресурса поверх изображения; конкретная геометрия и способы редактирования ещё выбираются |
| `ItemType`     | Вид предмета с названием, иконкой, признаком «сиденье» и числом посадочных мест на единицу                   |
| `ResourceItem` | Оснащение ресурса: вид предмета и количество; представление размещённых объектов сверяется с конструктором   |

Типы ресурса: рабочее место и переговорная.
Ресурс и его изображение на плане — связанные, но разные данные.
Тип описывает физический объект, а не допустимую цель использования.
Один сотрудник может забронировать переговорную для индивидуальной работы.
Если бронируется сама переговорная, бронь занимает её целиком и не меняет тип.
Каждое бронируемое рабочее место имеет собственный идентификатор,
индивидуальное положение на плане и свою занятость. Переговорная
представлена отдельной бронируемой областью.
Администратор размечает бронируемые области поверх изображения.
Изначально оснащение задавалось количеством по D-020. В параллельном
конструкторе пользователь позднее разрешил пространственное размещение
предметов и вывод состава из них по D-045. Окончательную связь конструктора,
геометрии предметов и данных бронирования нужно сверить после его готовности.

У рабочего места важны монитор, клавиатура, мышь, тип стула и тип стола.
У переговорной — вместимость, стол, доска, проектор и состав сидений.
Это примеры значимых характеристик, а не закрытые перечни.
Количество предметов и их разновидность — разные данные.
Предлагается задавать разновидности через общий справочник оснащения,
а формы и карточки адаптировать к типу ресурса.

Предметы описывают оснащение ресурса; отдельная бронируемость проектора
или стула из их наличия не следует. Количество мебели в переговорной
не создаёт автоматически отдельные бронируемые рабочие места.
Вместимость переговорной вычисляется
по оснащению с признаком «сиденье». В исходный набор входят стул,
кресло-мешок, фитбол, кресло и диван. Остальное названное оснащение —
стол, проектор и доска; уточнённое название — просто «доска».

Для диванов предусмотрены виды с указанным числом мест, например
двухместный и трёхместный. Отдельное число мест для каждой установленной
единицы вводить не нужно; способ задания количества уточняется
по результату параллельного конструктора.
Вместимость вычисляется как сумма количества предметов, умноженного
на число мест соответствующего вида. У одноместного сиденья одно место,
у прочего оборудования — ноль.

Редактируемость справочника и использование свойств при подборе
ещё рассматриваются в Q-05.
Геометрия областей и изменение подложки — Q-11.

Рабочие часы задаются через админку отдельно для каждого здания с настройкой
по дням недели — D-076. График применяется ко всем этажам и ресурсам здания.
При изменении часов существующие затронутые брони сохраняются как есть
с пометкой о необходимости пересмотра — D-078; новые брони проверяются
по новому графику. Это пересматривает прежнее решение об обрезке D-060.
Исключения для отдельных дат отложены — D-091. На рабочий день задаётся
один непрерывный диапазон без перерывов — D-094. Границы применения
изменения ещё выбираются в Q-06.

### Окружение ресурса

Окно, кофемашина, холодильник, кулер и туалет — объекты окружения на плане,
не отдельные цели бронирования. Их тип, этаж, геометрия и устойчивый ID
позволяют показывать окружение места и передавать его в будущий MCP-подбор.
Оснащение конкретного места и близость к объектам окружения — разные данные.
Геометрическое расстояние в единицах плана не означает расстояние пешком
или метры; расчёт маршрутов с учётом стен требует отдельной модели.

### Использование помещения целиком или по рабочим местам

Различаются потребность в помещении одному и потребность только
в отдельном месте с возможными соседями. Администратор явно включает
для конкретной переговорной настройку «Можно бронировать по местам».
Без включения этого режима переговорная бронируется только целиком.
При отключении режима существующие затронутые брони мест сохраняются
с пометкой о необходимости пересмотра — D-078. Новые брони отдельных мест
после отключения не создаются. Сохранённая помеченная бронь места продолжает
конфликтовать с бронью комнаты целиком до её изменения или отмены — D-080.

Рабочее место может быть явно связано
с родительской переговорной. Бронь переговорной занимает помещение целиком;
бронь отдельного места занимает только это место, если такой способ
использования разрешён для помещения.

Для этой модели необходимы правила:

- Бронь переговорной конфликтует с любой пересекающейся бронью её мест.
- Бронь места конфликтует с бронью того же места и переговорной целиком.
- Разные места могут бронироваться одновременно при разрешённом совместном использовании.
- Эти физические конфликты проверяются независимо от владельца брони.
- Проверка и создание или изменение атомарны для помещения и его мест,
  включая конкурентные запросы на комнату и отдельное место.

Сиденья в оснащении не превращаются автоматически в рабочие места.
Предлагается запрос «быть одному» отображать в форме как выбор
переговорной целиком, чтобы пользователь подтверждал фактический объём брони.
Общий доступ сотрудников к ресурсам не заменяет настройку допустимого
совместного использования помещения. Конкретная разметка рабочих мест,
представление режима и поведение при изменении настройки — Q-17 и Q-12.

Цвет переговорной и счётчик частичной занятости на плане зависят
от момента, выбранного курсором времени. Частичная занятость означает,
что занята часть отдельно бронируемых рабочих мест, а часть свободна;
комнату целиком в этот момент занять нельзя. Счётчик использует количество
рабочих мест, а не вычисляемую по мебели вместимость. Соседние интервалы
оцениваются по правилу `[start, end)`.
Курсор под шкалой показывает часы и минуты; его можно перетаскивать
или перемещать нажатием на доступную точку временной шкалы.
Доступность конкретного ресурса для бронирования отдельно проверяется
за весь выбранный интервал по D-065. Размещение этих двух показателей
в интерфейсе ещё не согласовано — Q-16.

## Бронирование

Проектируемая `Booking` связывает ресурс, владельца и интервал времени.
Предлагаемые поля: идентификатор, ресурс, владелец, начало, окончание и состояние.
При изменении условий существующая бронь может требовать пересмотра: она
сохраняется, а пользователь видит пометку — D-078. Для снятия пометки
нужно исправить бронь до соответствия актуальным условиям с серверной
проверкой; простого подтверждения ознакомления недостаточно — D-098.
Представление пометки и будущие оповещения обсуждаются в Q-12.
Автоматический пересмотр из-за изменений оснащения отложен — D-102;
правило сравнения оборудования с требованиями брони сейчас не реализуется.
Пометка не освобождает ресурс: сохранённый интервал продолжает участвовать
в проверке конфликтов до явного изменения или отмены брони — D-080.
Начало и конец относятся к одной календарной дате по московскому времени;
новый интервал укладывается в рабочие часы выбранной даты. Существующая
бронь, переставшая им соответствовать, сохраняется с пометкой по D-078.
Правило применяется к созданию, переносу и изменению длительности.
Начало и окончание при создании и пользовательском редактировании задаются
с единым шагом в форме, шкале и HTTP/MCP; сервер проверяет кратность — D-093.
По умолчанию шаг равен пяти минутам, а горизонт бронирования — неделе;
оба значения задаются переменными окружения — D-095. Горизонт считается
по календарным датам московского времени: при значении `N` разрешены даты
от сегодня до сегодня плюс `N - 1` дней включительно, со всеми рабочими
часами последней разрешённой даты. При `7` это сегодня и ещё шесть дней.
Новая бронь не начинается в прошлом. Ближайшее разрешённое начало —
ещё не прошедшая граница настроенного шага, например 10:05 при текущем
времени 10:02 и шаге пять минут; сервер проверяет это при создании — D-096.
Это не задерживает немедленное освобождение
при досрочном завершении.
При бронировании переговорной обязательно указывается число участников.
Это отдельное значение, не равное автоматически вместимости комнаты.
Для брони переговорной целиком превышение рассчитанного числа сидячих мест
показывается предупреждением и не запрещает стандартное подтверждение.
Рабочие места выбираются на плане как конкретные отдельные ресурсы.
В общих просмотрах показывается владелец, интервал и число участников
брони переговорной.
Это помогает сотрудникам договориться, но не передаёт им права
редактировать чужую бронь.
Указание меньшего числа участников не освобождает места внутри комнаты,
если забронирована переговорная целиком.

Для интервалов используем представление `[start, end)`: соседние интервалы
10:00–11:00 и 11:00–12:00 совместимы. Полная формулировка обязательных правил —
в разделе «Задача» [исходного задания](source/assignment.md).

Доступность ресурса вычисляется для выбранного интервала из действующих броней.
«Занято» не является постоянным полем ресурса, а «выбрано» является состоянием UI.
Интервалы одного пользователя для разных ресурсов разрешены: D-002.
В варианте с вложенными местами это не отменяет физических конфликтов
между помещением целиком и любым местом внутри него.

Предложены состояния «действует» и «отменена». Истечение времени можно
определять по интервалу, без отдельной смены состояния; это предложение,
которое ещё предстоит закрепить при описании жизненного цикла.

Для повторного подтверждения без дубликата выбран ключ идемпотентности,
создаваемый клиентом и сохраняемый вместе с бронью — D-120. Повтор одной
отправки сохраняет ключ и возвращает ту же бронь; новая попытка получает
новый ключ. `request_id` отдельной попытки и `trace_id` отличаются от ключа
идемпотентности; точные контракты хранения и корреляции ещё проектируются.
При отмене сотрудником уже начавшейся собственной брони интервал обрезается
по текущему времени, ресурс сразу освобождается, а прошедшая часть сохраняется
в истории — D-073. Представление истории и состояний обсуждается в Q-07,
административных изменений — в Q-12.
У начавшейся своей брони сотрудник может редактировать только окончание,
сокращая или продлевая его с проверками. Начало и ресурс фиксированы — D-097.
Сохранение прежнего начала при таком редактировании не является созданием
новой брони в прошлом.

## Диалог и предложение помощника

| Термин                          | Смысл и статус                                                                                                      |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Чат-сессия / `ChatSession`      | Отдельное обращение пользователя: идентификатор, владелец, время создания и сохранённая история сообщений           |
| Контекст LLM                    | Сообщения и данные, включённые в конкретный вызов модели; отделяется от полного хранимого архива                    |
| Предложение / `BookingProposal` | Набор параметров для предзаполнения формы; передаётся в URL без таймера и отдельной записи предложения в БД — D-118 |

Помощник получает актуальные варианты через MCP, показывает предложение
на плане и предзаполняет форму создания. Пользователь подтверждает
конкретные параметры в форме, после чего Booking проверяет и создаёт бронь.
По умолчанию встроенный помощник ищет в выбранном здании с учётом доступа
пользователя — D-084 и D-085.
Перенос и отмена через диалог в первую версию не входят.
Внешний MCP-клиент получает ссылку на нашу предзаполненную форму.
Результат её подтверждения показывается в нашем интерфейсе; автоматически
во внешний чат не отправляется — D-121.
Открытие предложения не создаёт и не удерживает бронь; создание
требует подтверждения пользователем в нашем интерфейсе.
Ссылку можно сохранять в закладки. Её параметры проверяются заново;
владелец новой брони определяется текущим удостоверенным контекстом.
Если дата из ссылки уже прошла по московскому времени, поле даты остаётся
пустым; остальные параметры сохраняются. Актуальную дату выбирает
пользователь — D-119.
URL не является ключом идемпотентности: повтор одной отправки и новое
подтверждение после открытия закладки — разные случаи — D-118.

Диалог ведётся до успешного создания брони, затем отправляется в архив —
D-082. Подходит любая новая бронь пользователя, включая ручную через форму.
У пользователя один общий активный диалог во всех вкладках. Сообщения,
ответы и смена текущего диалога синхронизируются через SSE — D-105.
Пока помощник отвечает, новая отправка заблокирована во всех вкладках,
очереди сообщений нет. Сервер обеспечивает одну активную обработку;
после её завершения или ошибки отправка доступна снова — D-106.
При конфликте или ошибке сохранения он остаётся открытым. Следующее
обращение начинает новую чат-сессию; прежние сохраняются как история.
Кнопка «Новый диалог» позволяет вручную отправить текущий чат в архив
без создания брони и начать новый с чистого контекста — D-099.
Прошлые сессии автоматически не передаются модели вместе с новым запросом.
В активном диалоге используется окно последних сообщений; старое обрезается
из контекста LLM, полная история в БД сохраняется — D-122.
Системные инструкции и текущий запрос сохраняются; связанные вызовы
инструментов и ответы не разрываются. Размер окна настраивается с моделью.
Архивные сессии доступны только для просмотра, без продолжения диалога
и повторного выполнения действий из сообщений. Просмотр архива не запускает
LLM или MCP. Старые предложения остаются историческими данными;
подтверждение из них не выполняется.
Сохранённая отдельно ссылка с параметрами может открыть новую форму;
её новое подтверждение не является выполнением старого действия из архива.
Ответ принадлежит исходному диалогу. Если он получен после архивирования,
то сохраняется в этот архив, не попадая в новый диалог или его контекст —
D-108. Это не возобновляет архивный диалог для пользовательских сообщений.
При возвращении на сайт, повторном входе и обновлении страницы
незавершённый диалог восстанавливается — D-082. История чатов сохраняется
без ограничения срока и автоматической очистки — D-104. Это не отменяет
отдельного ограничения контекста текущего обращения.

Сессия входа, чат-сессия и предложение брони имеют разные жизненные циклы.
Предложение до подтверждения не является созданной бронью.
Форма и предложение помощника не удерживают ресурс.
При сохранении Booking атомарно проверяет доступность и применяет
операцию либо возвращает конфликт. Форма выделяет занятое время
и сохраняет введённые данные для исправления.
Неуспешное изменение не меняет сохранённую бронь.

Повторяющиеся серии отложены; каждую бронь создают отдельно — D-081.
Одна бронь на один ресурс и непрерывный интервал, отсутствие групповых
операций — предложенные ограничения первой версии, пока не принятые решения.
Изменение интервалов в UI принято в D-028;
прежнее предложение ограничиться отменой и новой бронью пересмотрено.
Создание в UI выполняется через форму с подтверждением. Перенос и изменение
длительности уже созданной своей брони сохраняются при завершении жеста,
без отдельного подтверждения. Чужие полосы на шкале не редактируются.
Серверный контракт изменений и обработка конфликтов ещё выбираются.
