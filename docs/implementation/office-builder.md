# Конструктор офиса: первый фронтенд

Реализация находится в `apps/frontend`: React, TypeScript и Vite.
План загружается и сохраняется через Gateway. Текущие границы подключения и
перенос прежних браузерных данных описаны в [интеграции фронтенда](frontend-integration.md).
Экспорт отложен по просьбе пользователя.

## Запуск

Из корня монорепозитория:

```bash
make up
```

Вход: [localhost:5178](http://localhost:5178/). В профиле администратора открыть
«Администрирование» → «Офисы» → нужный офис → «Редактировать план».
Маршрут конструктора: `/admin/offices/:id/plan`.

```bash
docker compose -f compose.dev.yaml run --rm --no-deps frontend npm run build
docker compose -f compose.dev.yaml run --rm --no-deps frontend npm test
```

## Основной сценарий

1. Выбрать этаж вертикальными кнопками справа сверху или добавить пустой кнопкой «+».
2. Открыть «Подложка» над планом и загрузить изображение. Поддерживаются PNG, JPEG и WebP.
   После загрузки открывается редактирование с временным стулом для сравнения масштаба.
   Стул можно перемещать; его размер совпадает с каталогом и не меняется при растягивании
   изображения. Он не сохраняется как предмет и исчезает после «Готово».
   Подложка перемещается и масштабируется за углы с сохранением пропорций.
   Для повторного входа нажать «Редактировать подложку».
   Скрытие и непрозрачность доступны в той же панели.
3. Отметить помещения прямоугольными областями и при необходимости нарисовать стены.
4. Выбрать предмет в каталоге и поставить на плане. Поддерживается перенос из каталога мышью.
5. Выбрать объект и изменить название, положение, размер, поворот и свойства справа.

Масштаб здания не меняется при изменении размера окна. Меняется видимая
часть холста. Зум — колесом и кнопками; отдельная команда вписывает весь план.
Единицы координат внутренние, без заявления о масштабе в метрах.

## Объекты и связи

- Переговорная — область с названием, цветом, бронируемостью и настройкой совместного использования.
- Рабочее место — самостоятельный объект на плане, с собственным ID и бронируемостью.
- Мебель и техника размещаются отдельными объектами. Попадание в помещение связывает их с ним.
- Оснащение помещения и вместимость пересчитываются по связанным размещённым предметам.
- Перенос помещения переносит его содержимое; поворот и изменение границ учитывают связанные объекты.
- Количество сидений и число отдельных рабочих мест показываются раздельно.

Здесь описаны инструменты плана; авторизация, бронирование и границы помощника
описаны в [интеграции фронтенда](frontend-integration.md).

## Стены

Физические стены рисуются единым слоем фиксированной толщины.
Совпадающие и примыкающие участки объединяются, общая граница не удваивается.
Для области помещения можно отключить «Стены по контуру», когда стены уже
есть на изображении или нарисованы отдельно. В демонстрационном плане
физические стены и области помещений разделены.

Стена редактируется двумя концами оси, а не размером прямоугольника.
Есть привязка к концам и оси других стен с радиусом 8 экранных пикселей;
в свойствах доступны координаты обоих концов. Толщина при изменении длины
сохраняется. Близкие разные оси явных стен не объединяются автоматически.
Заполнение внешних углов и согласование угловой привязки обсуждались;
пользователь решил пока оставить текущее поведение.

## Каталог

В `public/assets/furniture/` находятся 22 авторских SVG вида сверху:
столы, стулья и кресла, мешок, фитбол, диваны на два и три места,
монитор, клавиатура, мышь, доска, проектор, растение и дверь.
В категории «Окружение» — окно, кофемашина, холодильник, кулер и туалет;
типы и координаты используются для пространственного контекста клиента.
Названия, размеры, категории и число мест описаны в `src/office/lib/catalog.ts`.

## Управление

| Действие                   | Клавиша или жест                                             |
| -------------------------- | ------------------------------------------------------------ |
| Выбор                      | V                                                            |
| Перемещение холста         | H или удержание пробела                                      |
| Стена                      | W, затем протянуть                                           |
| Помещение                  | R без выбранного объекта, затем протянуть                    |
| Поворот выбранного объекта | R или ручка над объектом                                     |
| Изменение размера объекта  | Ручка в правом нижнем углу или поля справа                   |
| Изменение стены            | Перетаскивание одного из концов или координаты концов справа |
| Точное перемещение         | Стрелки; Shift увеличивает шаг                               |
| Дубликат                   | Ctrl/Cmd D                                                   |
| Удаление                   | Delete/Backspace                                             |
| Отмена                     | Ctrl/Cmd Z                                                   |
| Повтор                     | Ctrl/Cmd Shift Z                                             |
| Завершить инструмент       | Esc                                                          |

Шаг привязки объектов — 5 единиц плана. Сетка рисуется линиями поверх
плана и подложки; крупные деления выделены сильнее. Видимый шаг зависит
от масштаба, чтобы линии не сливались при удалении; он указан внизу холста.
При входе в редактирование подложки сетка включается автоматически.
Есть блокировка объекта, управление слоями,
предпросмотр, прозрачность и видимость подложки.
Общее расписание офиса редактируется в настройках по дням недели.

## Сохранение

Этажи, объекты, связи и встроенные изображения сохраняются через
`PUT /api/offices/:id/plan`; название, адрес и расписание — отдельной командой
настроек. Обе команды передают базовую `revision`. Чтение офиса не записывает
план обратно. При конфликте версии черновик остаётся доступен, автоматической
перезаписи свежей серверной версии нет.

Браузер хранит отдельный черновик восстановления. Старые ключи
`plan-room.office-builder.v1` и `plan-room.offices.v1` остаются архивом;
их явный перенос описан в [интеграции](frontend-integration.md#браузерный-архив).

Файл изображения ограничен 20 МБ и оптимизируется до максимальной стороны
2200 px. Положение, размер и видимость подложки сохраняются отдельно от геометрии
этажа и объектов. Перемещение, масштабирование, скрытие и замена изображения
не перемещают мебель и помещения. Рамка подложки активна только в явном режиме
редактирования; изменения поддерживают отмену и повтор.
Ошибки серверного сохранения и записи черновика восстановления показываются в UI.

- Проверены удаление тестового этажа и возврат к исходному плану.
- Для подложки проверены скрытие, пропорциональное изменение размера углом,
  перемещение и завершение редактирования; координаты и размеры стола не изменились.
- После перезагрузки восстановлены положение и размер подложки; режим редактирования выключен.
- Проверены сетка поверх изображения, стыковка концов стены и отмена/повтор
  изменения длины.
- Проверен стул для масштаба: перемещение не меняет подложку, растягивание
  подложки не меняет позицию и размер стула 52×58; число объектов остаётся нулевым.

На этом этапе демонстрация содержала два этажа. История отмены сохраняется
только в текущем сеансе и не восстанавливается после перезагрузки.
