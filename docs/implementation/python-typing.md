# Статическая типизация Python

`make typecheck` собирает dev-образ и запускает закреплённый `mypy==2.4.1`
в Docker. Python, зависимости и кэш checker остаются внутри контейнера;
локальное окружение Python не требуется. Изменение зависимостей фиксируется
в `uv.lock` командой `make lock`, также через Docker.

## Область проверки

В корневом `pyproject.toml` включён `strict = true` для всего production-кода:

- `packages/platform/src`;
- `apps/users/src`;
- `apps/booking/src`;
- `apps/assistant/src`;
- `apps/gateway/src`.

Проверяются параметры и возвраты функций, generic-параметры коллекций,
ORM-модели, обработчики и фоновые задачи, интерфейсы RPC, MCP и SSE.
Пакеты содержат `py.typed`, чтобы их типы были доступны импортирующим пакетам.
Плагин `pydantic.mypy` с `init_typed = true` проверяет конструкторы моделей
и учитывает чтение обязательных настроек `BaseSettings` из окружения.

Тесты, Alembic-миграции и вспомогательные scripts не входят в эту статическую
проверку. Их проверяют Ruff и соответствующие исполняемые тесты. Проверка
TypeScript фронтенда остаётся отдельной.

## Границы данных

Сервисы сохраняют независимые модели: Gateway не импортирует доменные модели
из приложений Users, Booking или Assistant. В Gateway описаны только
потребляемые поля приватных ответов. Полученный из транспорта `object`
проверяется Pydantic перед использованием; несовместимый ответ преобразуется
в `502 upstream_contract_invalid`, без содержимого ответа и секретов в ошибке.

Интерфейсы внедряемых обработчиков описаны точными `Protocol` и `TypedDict`:
имена и типы аргументов MCP проверяются вместе с реализацией общего фасада.
Перегрузки RPC-вызова различают данные ответа и пару данных со статусом.
Официальные типы ASGI, NATS, HTTPX и SDK используются на границах библиотек.

Для расширяемых JSON-документов используется `pydantic.JsonValue`; неизвестное
до проверки значение имеет тип `object`. Непрозрачные расширения планов
сохраняются, включая явный `null`. Типизированный wrap-сериализатор плана
использует комментарий типа возврата: runtime-аннотация Pydantic подменяла бы
публичную схему документа общей схемой словаря.

Общие отключения ошибок, `ignore_missing_imports` и ослабление strict для
приложений не используются. Статическая проверка дополняет runtime-валидацию,
проверку прав и тесты конкурентных записей.

## Проверено 13.11.2026

- `make typecheck`: strict mypy, 72 production-файла без ошибок.
- `make lint`: Ruff check и форматирование, 130 Python-файлов.
- `make test`: 306 тестов, включая изолированные PostgreSQL/NATS,
  конкурентные записи, OAuth/MCP, SSE и сохранение JSON-расширений.
- OpenAPI Gateway: маршруты и схемы операций совпадают с состоянием до
  типизации. Расширяемые поля `ClientBooking` ссылаются на пустую JSON Schema
  `JsonValue` вместо `additionalProperties: true`, с тем же набором JSON-значений.

Тесты помощника используют детерминированную модель; этот прогон не вызывает
платный OpenRouter. Действующие dev/prod данные не участвовали в тестировании.
