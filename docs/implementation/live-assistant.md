Проверено 12.11.2026 на локальном Docker dev через Nginx
`http://localhost:5178/booking`. Это реальный вызов OpenRouter,
а не TestModel/FunctionModel. Публичный HTTPS и сторонний MCP-клиент
этим прогоном не проверяются.

Это историческое свидетельство от 12.11.2026. Дата 13 ноября ниже относится
к выбранному интервалу тестовой брони.

## Конфигурация

Пользователь выбрал **`~deepseek/deepseek-flash-latest`**, включая тильду, — D-127.
Каталог API OpenRouter подтвердил этот ID и поддержку инструментов.
В SDK-ответах успешного запуска фактическая модель:
`deepseek/deepseek-v4.1-flash-1017`, провайдер `openrouter`.

Ключ сохранён только в игнорируемом `.env` с правами `0600`; в этот отчёт,
JSON-доказательство и код его значение не включается. API и worker Assistant
пересозданы с новым окружением. `configuration_status()` возвращает
`generation_available=true`, `missing_configuration=[]`.

Чтобы настроить свой dev, задать в `.env`:

```dotenv
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_MODEL=~deepseek/deepseek-flash-latest
```

После изменения окружения:

```sh
docker compose -f compose.dev.yaml up -d --no-deps --no-build --wait assistant assistant-generations
```

Ключ вводится в файл окружения и не требуется в React, URL или сообщении модели.

## Найденная ошибка и исправление

Первый живой запрос завершился ошибкой: модель передала `participants=1`
для рабочего места. Gateway правильно отказал, поскольку число участников
задаётся для переговорной. Assistant был настроен на
`tool_error_behavior="error"`, из-за чего обычная ошибка аргументов прерывала run.
Бронь при этом не появилась.

Исправлено:

- MCP использует штатный `tool_error_behavior="retry"` Pydantic AI: ошибка
  инструмента возвращается модели для коррекции в пределах существующего
  бюджета повторов и запросов.
- Инструкция явно задаёт `participants` только для переговорной;
  для рабочего места параметр пропускается либо равен `null`.
- Реальная валидация Gateway/Booking сохранена, некорректные аргументы
  не исправляются молча в бизнес-слое.

Во втором живом запросе DeepSeek передал `participants:null` и завершил подбор.
Сам путь коррекции после ошибки отдельно проверен детерминированной моделью
через настоящий HTTP MCP: неверные аргументы → retried tool result → исправление
→ grounded proposal. Постоянная ошибка даёт ровно две попытки при одном retry,
затем конечную ошибку; бесконечного цикла нет.

Проверки в Docker:

```sh
docker compose -f compose.dev.yaml run --rm --no-deps dev pytest -q \
  apps/assistant/tests/test_llm_runtime.py \
  apps/assistant/tests/test_generation_mcp.py
```

Результат от 12.11.2026: **26 passed, 5.68 s**; Ruff check и format check
изменённых файлов прошли.
Эти автотесты не выполняют платных запросов. Описанный выше браузерный прогон
отдельно подтверждает работу выбранной реальной модели.
Поведение ошибок соответствует
[официальному контракту MCPToolset](https://pydantic.dev/docs/ai/mcp/client/#tool-errors).
